# Key Point
- **운영체제** = 하드웨어와 프로그램 사이에서 **리소스를 제어**하고 **프로그램 실행을 돕는 시스템 소프트웨어**
- CPU는 직접 처리하지만, 처리할 **명령어·데이터**는 먼저 **메모리**에 올라와야 함
- 운영체제의 핵심 역할 = **프로세스, 메모리, 파일 시스템, 네트워크** 관리
- **리소스**는 프로그램 실행에 필요한 자원, 강의에서는 주로 **메모리** 중심
- 여러 운영체제는 사용 목적이 다름: **Windows = 일반 사용자**, **macOS = 개발 친화**, **Linux = 서버·개발**, **컨테이너 = 환경 통일**

---
# 강의 흐름
- 컴퓨터 하드웨어 복습 → 운영체제 개념과 필요성 → 리소스 의미 → 운영체제 주요 기능 → 운영체제 종류와 컨테이너화

---
# 핵심 내용 정리
## 컴퓨터 하드웨어 복습
- **CPU**
    - 컴퓨터의 중앙 처리 장치
    - 대부분의 연산 처리
    - 처리에 필요한 것: **명령어 + 데이터**
    - CPU는 주로 **메모리의 정보**를 가져와 동작
- **메모리**
    - CPU가 처리할 **데이터와 명령어** 저장
    - 주소를 기준으로 데이터 탐색
    - 보조기억장치보다 빠르지만 전원이 꺼지면 내용 삭제
- **주변장치**
    - **입력 장치**: 마우스, 키보드
    - **출력 장치**: 모니터, 스피커, 프린터
    - **보조기억장치**: SSD, HDD
- 💡 CPU가 바로 SSD/HDD를 읽는 것이 아니라, 데이터를 **메모리로 불러온 뒤 처리**
- ⚠️ “파일을 실행한다” = 실제로는 필요한 데이터가 **메모리에 올라오는 과정** 포함

---
## 운영체제의 개념
- **운영체제**
    - 하드웨어를 포함한 **리소스 제어**
    - 프로그램 실행 지원
    - 프로그램과 하드웨어 사이의 **중간 관리자**
- 운영체제가 필요한 이유
    - 하드웨어 종류 증가
    - 개발자가 모든 하드웨어 구조를 직접 알기 어려움
    - 프로그램이 다양한 환경에서 실행되도록 지원 필요
- _회사 비유_: 사장이 모든 직원을 직접 관리하기 어려워지면 팀장·부서장이 필요 → 컴퓨터에서는 운영체제가 그 역할
- 💡 운영체제의 본질: **프로그램이 하드웨어를 직접 다루지 않아도 실행되게 만드는 층**
- ⚠️ 운영체제는 단순 실행 도구가 아니라, **자원 배분과 보호**까지 담당

---
## 리소스와 자원 제어
- **리소스**
    - 어떤 목적에 이용할 수 있는 컴퓨터 자원
    - 강의에서는 특히 **메모리**가 핵심 예시
- 프로그램 실행에는 메모리 공간 필요
    - 각 프로그램마다 할당된 공간 존재
    - 한 프로그램이 다른 프로그램의 공간을 마음대로 침범 불가
    - 운영체제가 리소스를 **할당·회수·보호**
- 메모리 부족 오류의 의미
    - 현재 사용할 수 있는 메모리 부족
    - 다른 프로그램 종료 시 메모리 확보 가능
    - 프로그램별 리소스가 분리되어 있음을 보여줌
- 💡 운영체제는 리소스를 “나눠주고”, “뺏고”, “침범하지 못하게 막는” 역할
- 📊 제안: 대용량 데이터 처리에서 메모리 오류가 나면 코드 문제뿐 아니라 **리소스 할당 한계**도 먼저 의심

---
## 운영체제의 주요 기능
- 운영체제는 프로그램이 잘 실행되도록 여러 기능 제공
- 강의에서 다룬 핵심 기능
    - **프로세스 관리**
    - **메모리 관리**
    - **파일 시스템 관리**
    - **네트워크 관리**
- 💡 운영체제 공부 = 각 기능이 **어떻게 동작하고 관리되는지** 배우는 것

---
## 프로세스 관리
- **프로세스** = 실행 중인 프로그램
- 컴퓨터는 보통 여러 프로그램을 동시에 실행
    - 음악 재생, 게임, 영상 시청, 채팅 등
- 운영체제의 프로세스 관리 역할
    - 프로세스마다 필요한 리소스 할당
    - 종료된 프로세스의 리소스 회수
    - 각 프로세스의 상태 관리
    - 여러 프로세스를 동시에 실행하는 **멀티 프로세싱** 지원
- 💡 프로세스 관리는 “누가 CPU와 메모리를 언제 얼마나 쓸지” 관리하는 문제
- ⚠️ 종료된 프로그램이 리소스를 계속 잡고 있으면 낭비 발생

---




## 메모리 관리
- 프로그램 실행을 위해 필요한 정보는 **메모리**에 올라가야 함
- 운영체제는 메모리에 데이터를 올리고, 실행 후 정리
- 핵심 역할
    - 프로그램 실행에 필요한 데이터 적재
    - 프로세스에 필요한 메모리 할당
    - 사용이 끝난 메모리 회수
- 💡 CPU가 실행하려면 먼저 메모리에 올라와야 함
- 📊 제안: 분석 코드가 느리거나 죽을 때는 **CPU보다 메모리 사용량**이 병목인 경우가 많음

---
## 가상 메모리
- **가상 메모리**
    - 실제 주소가 아닌 **가상의 주소**로 메모리 관리
    - 프로세스가 실제 메모리 주소를 직접 알지 못하게 함
- 장점
    - **정보 보호**: 실제 주소를 모르면 다른 메모리 공간을 직접 건드리기 어려움
    - **연속 주소 제공**: 프로세스 입장에서는 큰 메모리를 연속으로 받은 것처럼 보임
    - 주소 관리 부담 감소
- _안심번호 비유_: 택배기사는 진짜 번호를 몰라도 연락 가능 → 프로세스는 실제 메모리 주소를 몰라도 실행 가능
- ⚠️ 가상 메모리는 “메모리가 무한해진다”가 아니라, **주소를 가상화해서 관리하기 쉽게 만드는 기술**
- 📊 제안: 데이터 처리 중 메모리가 부족하면 가상 메모리만 믿기보다 **데이터 크기·청크 처리·메모리 해제** 점검 필요

---
## 파일 시스템 관리
- **파일 시스템**
    - 저장 장치에 파일을 읽고 쓰는 방식
    - 프로그램이 저장 방식의 차이를 직접 고민하지 않도록 운영체제가 관리
- 운영체제의 역할
    - 어떤 저장 방식이든 프로그램이 파일을 읽고 쓸 수 있게 지원
    - 저장 장치와 프로그램 사이의 세부 처리 감춤
- 💡 파일 저장은 단순히 “디스크에 쓴다”가 아니라, 운영체제의 **파일 시스템 규칙**을 거침

---
## 네트워크 관리
- 운영체제는 네트워크 통신도 지원
- **프로토콜**
    - 컴퓨터끼리 통신하기 위한 규칙
- 운영체제의 역할
    - 다양한 프로토콜 지원
    - 포트 관리
    - 이미 사용 중인 포트 보호
- _활주로 비유_: 사용 중인 활주로에 다른 비행기가 들어오지 못하게 막는 관제탑 역할
- ⚠️ 포트 충돌은 프로그램 문제가 아니라, 운영체제의 **자원 사용 충돌**로 볼 수 있음

---
## Windows
- Microsoft의 데스크톱 운영체제
- 일반 사용자에게 적합
- 높은 점유율
- 상용 소프트웨어
- 💡 강의 기준: **일반 사용자 중심 운영체제**

---
## macOS
- Apple의 데스크톱 운영체제
- **Unix 기반**
- Unix 계열 터미널 명령어 사용 가능
- 개발 환경에 비교적 적합
- 상용 소프트웨어
- 💡 강의 기준: **개발 친화적 데스크톱 환경**

---
## Linux
- **오픈소스** 운영체제
- 무료, 자유로운 라이선스
- 원하는 방식으로 수정 가능
- Ubuntu, Debian 등 다양한 배포판 존재
- Android도 Linux 기반
- 안정적이고 여러 사용자가 동시에 쓰기 적합
- 서버와 개발 환경에 많이 사용
- 💡 강의 기준: **서버·개발에 적합한 운영체제**
- 📊 제안: 데이터 분석 실무에서 서버, 클라우드, 배포 환경은 Linux 기반인 경우가 많아 기본 명령어 이해 중요

---
## 컨테이너화
- 운영체제마다 개발 환경이 달라지는 문제에서 출발
- 서버는 대부분 Linux인데 개인 컴퓨터는 Windows/macOS인 경우 많음
- **컨테이너화**
    - 필요한 운영체제 환경과 패키지를 묶어 실행
    - 사용 중인 운영체제와 상관없이 비슷한 개발 환경 구성 가능
    - Docker가 대표 예시
- 💡 컨테이너의 핵심: “내 컴퓨터에서는 됐는데 서버에서는 안 됨” 문제 감소
- 📊 제안: 분석 프로젝트 재현성 확보에는 **패키지 버전 + 실행 환경 통일**이 핵심

# 공통 주의점
- ⚠️ CPU, 메모리, SSD/HDD 역할 혼동 금지
    - CPU = 처리
    - 메모리 = 실행 중 데이터
    - SSD/HDD = 장기 저장
- ⚠️ 운영체제를 “화면이 있는 프로그램” 정도로 이해하면 부족
    - 핵심은 **리소스 관리와 보호**
- ⚠️ 리소스 부족은 단순 용량 문제가 아니라, **프로그램별 할당·격리·회수** 문제와 연결
- ⚠️ 가상 메모리 = 실제 메모리 증가가 아니라 **주소 관리 방식**
- ⚠️ 운영체제 종류는 취향 문제가 아니라 **사용 목적과 실행 환경**의 문제
