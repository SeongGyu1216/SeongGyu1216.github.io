- 1. <mark style="background: #ABF7F7A6;">성능 데이터 모델링</mark>
    - <mark style="background: #ABF7F7A6;">성능 데이터 모델링이란?</mark>
        - 자료 기준 정의:
            - 데이터베이스 <mark style="background: #FFF3A3A6;">성능 향상을 목적</mark>으로 수행하는 모델링 작업
        - 핵심:
            - “DB가 돌아가게 만드는 것”이 아니라
            - “<mark style="background: #FFF3A3A6;">빠르고 안정적으로 동작</mark>하게 만드는 것”
    - <mark style="background: #ABF7F7A6;">왜 중요한가?</mark>
        - 자료 핵심 설명:
            - <mark style="background: #FFF3A3A6;">쿼리 1개가 내부적으로 매우 많은 작업을 수행</mark>할 수 있다.
            - <mark style="background: #FFF3A3A6;">자주 실행되는 비효율 쿼리는 DB 전체 성능에 영향 </mark>가능
            - <mark style="background: #FFB8EBA6;">구조 자체가 잘못되면</mark>:
                - 원하는 <mark style="background: #FFB86CA6;">조회가 어려워지고</mark>
                - 불필요한 JOIN 증가
                - <mark style="background: #FFB86CA6;">중복</mark> 접근 증가
                - <mark style="background: #FFB86CA6;">성능 저하</mark> 발생
    - <mark style="background: #ABF7F7A6;">쉬운 말</mark>로 다시 말하면
        - SQL 속도 문제는:
            - SQL 문법만의 문제가 아니다.
        - 테이블 구조 자체가:
            - 조회 패턴에 안 맞으면
            - 아무리 SQL을 고쳐도 한계가 생긴다.
        - 예:
            - 주문 조회를 자주 하는데
            - 고객 정보가 지나치게 분리되어 있으면
            - JOIN이 반복 발생
            - → 조회 비용 증가
